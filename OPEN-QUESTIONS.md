### 2026-09-23 — #13 resolved: Predictive Analytics Dashboard built
The UI #13 asked about now exists (`/insights`, `frontend/src/features/insights/InsightsPage.tsx`,
backend `GET /predictive-analytics/summary` + `GET /predictive-analytics/forecast/:productId`).
"Projected spend" was defined as **recommended order quantity × unit cost**, using the exact same
deterministic `calculateReorder` function the daily replenishment review uses (§8.2) — not the
`dailyUsage × unitCost × 30` proxy #13's investigation used to sanity-check that real numbers
existed. The two are deliberately different: the proxy estimated a flat 30-day burn rate across
every product; the shipped panel only totals products that actually need reordering right now
(8 of 50 in the seeded data), which is the more defensible "money" number for a real approval
flow — it matches what the replenishment engine would actually recommend, not a hypothetical
month of consumption. Conservative choice made without asking: the KPI card is labelled
"Projected reorder spend" without a "(30 days)" qualifier (the task's own example text used that
phrasing) because the underlying `suggestedQty` formula (§8.2: `max(maxLevel - currentStock,
dailyUsage × leadTimeDays × 1.5)`) is not itself a strict 30-day figure, and CLAUDE.md's
determinism principle (§8.3) explicitly warns against overclaiming what a number means. | You — confirm this reads correctly as an investor number, or say if a literal trailing-30-day
spend estimate (the proxy formula) is what should be shown instead. |
